# CampusPulse — Oracle Database 21c Configuration & Administration Guide
### Authoritative Production Setup for University Evaluation

## 1. Overview & Architecture

**CampusPulse** designates **Oracle Database 21c Express Edition (XE) / Free** as its primary and authoritative relational database. The platform leverages Oracle-specific enterprise capabilities:
- **Pluggable Database (PDB) Architecture** (`XEPDB1`)
- **Native Identity Sequences** (`NUMBER GENERATED BY DEFAULT AS IDENTITY`)
- **PL/SQL Compound Triggers** to eliminate the classic `ORA-04091 mutating-table` error
- **Row-Level Pessimistic Locking** (`SELECT ... FOR UPDATE`)
- **Timezone-Aware Temporal Arithmetic** (`TIMESTAMP WITH TIME ZONE`)
- **Pre-compiled SQL Analytical Views** (`v_dashboard_summary`, `v_room_live_status`)
- **Composite B-Tree Performance Indexes**

## 2. Oracle Database Prerequisites & Services

### Windows Services Architecture
CampusPulse connects to the local Oracle 21c XE installation. Ensure the following Windows services are in the `Running` state:
1. `OracleServiceXE`: The Oracle Database 21c instance.
2. `OracleOraDB21Home1TNSListener`: The TNS network listener on port `1521`.

#### Verify Services via PowerShell:
```powershell
Get-Service *oracle* | Select-Object Name, Status, DisplayName
```

Expected Output:
```
Status   Name                                DisplayName
------   ----                                -----------
Running  OracleOraDB21Home1TNSListener       OracleOraDB21Home1TNSListener
Running  OracleServiceXE                     OracleServiceXE
```

If any service is stopped, start it via PowerShell as Administrator:
```powershell
Start-Service OracleServiceXE
Start-Service OracleOraDB21Home1TNSListener
```

## 3. Dedicated User & Schema Provisioning

Oracle 21c utilizes a Container Database (CDB) and Pluggable Database (PDB) hierarchy. CampusPulse resides in the default pluggable container `XEPDB1`.

### SQL Script: `create_oracle_user.sql`
Run the provided script using `sqlplus` as `sysdba`:
```powershell
sqlplus / as sysdba @backend\scripts\create_oracle_user.sql
```

The script performs the following idempotent provisioning:
```sql
ALTER SESSION SET CONTAINER = XEPDB1;

-- Drop user if exists
BEGIN
   EXECUTE IMMEDIATE 'DROP USER campuspulse CASCADE';
EXCEPTION
   WHEN OTHERS THEN
      IF SQLCODE != -1918 THEN RAISE; END IF;
END;
/

-- Create dedicated project user
CREATE USER campuspulse IDENTIFIED BY campuspulse123
DEFAULT TABLESPACE USERS
TEMPORARY TABLESPACE TEMP
QUOTA UNLIMITED ON USERS;

-- Grant required enterprise privileges
GRANT CONNECT, RESOURCE, CREATE VIEW, CREATE TABLE, CREATE SEQUENCE TO campuspulse;

EXIT;
```

## 4. Schema Deployment & Compilation

You can compile the full schema using either **SQL\*Plus** (Oracle Native CLI) or the automated **Python backend initializer**.

### Option A: Deployment via SQL\*Plus CLI
Execute the pure Oracle DDL script `oracle_schema.sql`:
```powershell
sqlplus campuspulse/campuspulse123@localhost:1521/XEPDB1 @backend\scripts\oracle_schema.sql
```

This compiles:
1. Safe drop blocks for existing tables and views
2. 6 Relational 3NF Tables with constraints
3. PL/SQL Compound Trigger `trg_no_overlapping_bookings`
4. Analytical Views `v_dashboard_summary` and `v_room_live_status`
5. 8 Performance B-Tree Indexes

### Option B: Automated Deployment & Seeding via Python
```powershell
# From the project root
$env:DATABASE_URL="oracle+oracledb://campuspulse:campuspulse123@localhost:1521/?service_name=XEPDB1"
backend\venv\Scripts\python.exe backend\scripts\init_db.py
```

This initializes the schema and seeds 5 buildings, 25 rooms, 10 users, 12 bookings, 6 tickets, and 6 campus events idempotently.

## 7. Performance Indexes & Optimization Strategy

The schema includes 8 purpose-built B-Tree indexes:

| Index Name | Table | Indexed Columns | Justification & Performance Benefit |
| :--- | :--- | :--- | :--- |
| `idx_rooms_bld_status` | `ROOMS` | `(building_id, status)` | Accelerates building-filtered availability queries and spatial map rendering. |
| `idx_bk_room_time` | `BOOKINGS` | `(room_id, start_time, end_time)` | High-performance composite index covering temporal conflict lookups and NOT EXISTS checks. |
| `idx_bk_user_id` | `BOOKINGS` | `(user_id)` | Foreign key index preventing unindexed FK table locks during user operations. |
| `idx_mt_status_pri` | `MAINTENANCE_TICKETS`| `(status, priority)` | Composite index accelerating urgent dispatch queries and dashboard ticket counters. |
| `idx_mt_room_id` | `MAINTENANCE_TICKETS`| `(room_id)` | Foreign key index speeding up room work order histories and cascade deletes. |
| `idx_mt_user_id` | `MAINTENANCE_TICKETS`| `(user_id)` | Foreign key index accelerating user profile ticket lookups. |
| `idx_events_start` | `EVENTS` | `(start_time)` | Accelerates chronological event timeline ordering and upcoming event filtering. |
| `idx_events_bld_room`| `EVENTS` | `(building_id, room_id)`| Foreign key index speeding up campus map event overlays and zone schedules. |

## 8. Common Oracle Troubleshooting Guide

### Error 1: `ORA-12541: TNS:no listener`
- **Cause**: The Oracle TNS Listener service is stopped.
- **Fix**: Run PowerShell as Administrator: `Start-Service OracleOraDB21Home1TNSListener`.

### Error 2: `ORA-01017: invalid username/password; logon denied`
- **Cause**: Incorrect password or connecting to CDB root (`localhost:1521/XE`) instead of the pluggable database (`XEPDB1`).
- **Fix**: Verify your `.env` specifies `?service_name=XEPDB1`. If needed, re-run `create_oracle_user.sql`.

### Error 3: `ORA-04091: table BOOKINGS is mutating, trigger/function may not see it`
- **Cause**: Standard row triggers (`AFTER INSERT FOR EACH ROW`) cannot query the table being modified.
- **CampusPulse Solution**: Implemented an **Oracle Compound Trigger** (`COMPOUND TRIGGER`). The trigger collects affected room IDs and booking intervals in `AFTER EACH ROW`. In `AFTER STATEMENT`, it acquires pessimistic row locks (`SELECT ... FOR UPDATE`) on the parent `ROOMS` table in deterministic sorted order to serialize concurrent direct SQL transactions, then validates half-open interval overlap with zero mutating-table errors.

### Error 4: `ORA-20001: OracleSQL Conflict Error: Room ... has an overlapping booking`
- **Cause**: This is the expected and intended business rule trigger firing when an overlapping reservation is attempted.
- **CampusPulse Handling**: Caught in FastAPI backend and translated to clean `HTTP 409 Conflict`.
